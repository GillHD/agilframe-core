# Подготовка релиза

Под личным аккаунтом GitHub заведите **AgilFrame** в разделе Projects. Описание проекта — «Встраиваемые видеозвонки, трансляции и голосовые комнаты на WebRTC для своей инфраструктуры». Свяжите с ним репозитории по мере их выпуска.

| Репозиторий | Структура | Когда выделять |
| --- | --- | --- |
| **agilframe** | `agil/core/` — Core, панель, редактор и общие пакеты. `agil/websdk/` — виджет и клиентский SDK. `agil/mobile/` — мобильные модули. `agil/edge/`, `agil/infra/`, `docs/` — медианоды, развёртывание и руководства. | Первый выпуск. Общие npm workspaces и lockfile обеспечивают сборку полного продукта. |
| **agilframe-examples** | `web/`, `mobile/`, `integrations/`. Примеры собственного интерфейса и интеграции с приложением. | После выпуска версионированного SDK, чтобы примеры работали после отдельного клонирования. |
| **agilframe-deploy** | `compose/`, `helm/`, `terraform/`, `runbooks/`. | Если манифесты начнут выпускаться своим циклом. Ссылки на версии Core и образы закрепляются в манифестах. |

Документация остаётся рядом с кодом, поскольку Core публикует часть материалов через встроенную Wiki. Выделение SDK возможно после публикации версионированных общих пакетов и замены локальных workspace-связей на зависимости от релизных версий.

## Проверка перед отправкой

1. Просмотрите `git diff --cached --name-only` и `git diff --cached --check`.
2. На первом коммите выгрузите индекс в новый пустой временный каталог через `git checkout-index --all --prefix=/path/to/temp/` и проверьте его с `gitleaks dir /path/to/temp --redact`. После первого коммита также выполните `gitleaks git --redact`. Проверьте оставшиеся ссылки и содержимое изображений.
3. Выполните `npm ci`, `npm run build`, `npm run typecheck`, `npm test` и `node agil/core/scripts/e2e.mjs --only=api`.
4. При публикации создайте пустой репозиторий с выбранной видимостью и отправьте только проверенную историю этой копии. Перед публикацией подтвердите права на выпуск под выбранной лицензией и укажите канал для коммерческих запросов.

В конфигурациях примеров используются локальные и зарезервированные домены. Адрес и секреты рабочего окружения задаются при развёртывании.
