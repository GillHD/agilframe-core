# План публикации AgilFrame

Все репозитории принадлежат `GillHD`. Общая доска [AgilFrame](https://github.com/users/GillHD/projects/1) связывает задачи и pull requests. `agilframe` содержит общую карту проекта и Git-подмодули. `agilframe-core` хранит исходный код и полную сборку для комплексной приёмки.

## Репозитории

| Репозиторий | Содержимое | Что требуется для использования |
| --- | --- | --- |
| `agilframe` | Общий README, план выпуска, Git-подмодули | Git и `git clone --recurse-submodules` |
| `agilframe-core` | Core, админка, редактор, общие пакеты, полная сборка и Wiki | Node.js и npm либо Docker |
| `agilframe-websdk` | Виджет, SDK, Web Component, демо, закреплённая копия протокола и рендера публичной Wiki | Сборка из своего lockfile. Для живого звонка нужен доступный Core |
| `agilframe-mobile` | Android, iOS, Flutter, React Native, Capacitor | npm для JS-обёрток. Для платформенных модулей — соответствующая toolchain. Для звонка нужен Core |
| `agilframe-nodes` | Образ медианоды, STT, Node Agent и Compose | Node.js для локальных тестов и Docker для развёртывания. Для регистрации ноды нужен Core |
| `agilframe-edge` | Агент публикации медиа для встраиваемых устройств | Node.js, FFmpeg и серверный RTMP Ingress |
| `agilframe-deploy` | Самостоятельный Compose-профиль Core, шаблон окружения и порядок обновления | Docker Compose. Source context закреплён на коммите исходного репозитория |
| `agilframe-examples` | Автономный веб-пример входа в комнату через iframe и ссылки на API | Статический HTTP-сервер, Core и токен участника |

## Порядок публикации

1. Зафиксировать коммит исходного репозитория. Переносить только проверенные файлы, отслеживаемые Git. Для каждого репозитория сохранить ссылку на исходную версию, лицензию и уведомления.
2. В SDK выделить самостоятельные workspaces и lockfile. Проверить установку из чистой папки, сборку, типы и тесты. Для нод проверить автономность build context, юнит-тесты и шаблоны Compose.
3. Проверить примеры на локальном Core и проверить манифесты развёртывания. Указать ограничения тестирования и требования к инфраструктуре в README каждого репозитория.
4. В GitHub создать публичные репозитории и отправить код от имени владельца. Связать каждый репозиторий с общей доской, добавить короткие описания и ссылки друг на друга. Проверить доступность исходников и инструкций без входа.
5. Вносить изменения компонентов в их самостоятельных репозиториях. Обновлять копии для интеграционной сборки Core вместе с закреплёнными SHA. Агент Edge загружается из отдельного репозитория даже в интеграционном тесте. Совместимость комплекта проверяется в общем CI. [Порядок обновления](https://github.com/GillHD/agilframe/blob/main/docs/repositories.md)

Независимое клонирование обеспечивает сборку компонента. Интерактивная встреча и зарегистрированная медианода взаимодействуют с запущенным Core.
