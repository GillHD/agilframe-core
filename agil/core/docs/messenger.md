# Интеграция звонков в корпоративный мессенджер

Сценарий: сотрудники общаются в корпоративном мессенджере (Telegram/Slack/Teams/
Matrix/свой веб-мессенджер), и прямо из чата могут начать звонок — **1:1 (P2P)**
или **групповой** в беседе. Чат остаётся мессенджерным (наш встроенный чат можно
отключить), звонок встраивается как часть интерфейса, разворачивается на
полный экран или открывается в отдельной вкладке.

## 1. Модель

| Сценарий | Комната | Участники | Что делает мессенджер |
|---|---|---|---|
| Личный звонок 1:1 | `mode:'direct'`, `transport:'p2p'`, `maxParticipants:2` | 2 | создаёт комнату, шлёт invite-ссылку собеседнику |
| Групповой звонок в беседе | `mode:'group'`, `context.conversationId` | N (mesh ≤8; для 3+ рекомендуется SFU) | создаёт комнату на беседу/встречу, шлёт карточку звонка |
| Звонок в канале/вебинаре | `mode:'group'` + `webinarMode` | N | карточка «подключиться» |

Комнаты создаются с контекстом:
```jsonc
POST /v1/admin/rooms
{
  "tenantId": "acme",
  "name": "Звонок с Анной",
  "mode": "direct",
  "transport": "p2p",
  "context": { "messenger": "corp-chat", "conversationId": "dm-42", "directPeerId": "user-7", "title": "1:1" },
  "maxParticipants": 2
}
→ { room, joinUrl, embedUrl, passwordProtected }
```
`room.mode` и `room.context` возвращаются в `RoomInfo` (создание, join,
welcome, admin room detail) и уходят в вебхук `room.created`. P2P — только для
1:1: 2 места, медиа напрямую, без серверной записи/трансляции (409
`p2p_unsupported`), см. `agil/core/docs/p2p.md`.

## 2. Поток «позвонить из чата»

### Права в окне звонка

В демо токен организатора получает создатель комнаты. Ссылка для приглашения открывает вход гостя. Порядок подключения и имя участника не меняют его роль.

В корпоративной интеграции бэкенд проверяет, что сотрудник состоит в беседе, создаёт комнату через `POST /v1/admin/rooms` с `allowedParticipantIds` и выдаёт каждому отдельный токен через `POST /v1/tokens`. Для инициатора укажите роль `host`, для администратора конкретного звонка — `moderator`, для остальных — `guest`. Передавайте стабильный идентификатор сотрудника как `participant.participantId`. Корпоративный ключ остаётся на бэкенде, браузер получает токен конкретной комнаты.

Роли и точечные права настраиваются в админ-панели или через `/v1/admin/access-policy`. Для собственной роли бэкенд передаёт в токене `roleId`. Для браузерной записи включите `features.recording` и `session.recording.enabled`; право `recording` по умолчанию есть у организатора и модератора. Оставьте `session.recording.consentRequired` включённым и покажите подтверждение. Если UI написан на headless SDK, берите права из `getState().permissions`, а индикатор — из `getState().recording.active` и `getState().recording.remoteActive`.

```
Пользователь A нажимает «Позвонить» в чате компании
  → бэкенд компании: POST /v1/admin/rooms {mode:'direct', transport:'p2p', context:{conversationId,...}}
  → получает joinUrl/embedUrl (+ токен для A через POST /v1/tokens)
  → мессенджер рисует карточку звонка в переписке (joinUrl)
  → A открывает звонок: inline (iframe/SDK) или в новой вкладке
  → B получает карточку, открывает joinUrl → POST /v1/rooms/:id/join → звонок
```
Групповой: один `conversationId` → одна комната на беседу (или новая на каждую
встречу). Приглашения — `POST /v1/admin/rooms/:id/invites` (TTL), карточка в
чате; события `participant.joined/left`, `call.ended` (webhooks) обновляют
карточку/статус в мессенджере.

## 3. Встраивание и чат

- **Чат.** `session.chat.ui = 'hidden'` (или `'external'`) — внутренний чат
  выключен/заменён чатом мессенджера; сообщения звонка можно не показывать.
  Для гибрида: `providers.chat.mode='external'` — виджет не рисует чат, а
  компания шлёт/принимает сообщения через SDK/postMessage/API
  (`POST /v1/admin/rooms/:id/chat`), т.е. **чат остаётся один — мессенджерный**.
- **Как часть страницы:** `layout.chrome='none'` + `inheritHostStyles` — без
  своей шапки/фона, выглядит как элемент мессенджера; `layout.mode='grid'` или
  `'spotlight'` (для 1:1 — спотлайт).
- **Полный экран по кнопке:** `instance.requestFullscreen()` или кнопка в
  контролах; выход — `exitFullscreen()`/Esc.
- **Новая вкладка:** `instance.openInNewTab()` (использует `AGILCalls.createCallUrl`)
  или `window.open(joinUrl)`; состояние комнаты/токена передаётся в URL.
- **Свернуть в мини-окно:** `layout.minimized` + `minimize()` — звонок висит
  поверх мессенджера, пока пользователь листает чаты; в Electron — отдельное
  always-on-top окно (`agil/core/docs/electron.md`).
- `persistAcrossPages`/`resume()` — переходы между страницами мессенджера.

## 4. Варианты по платформам

| Мессенджер | Как встроить | Замечания |
|---|---|---|
| Свой веб-мессенджер | SDK inline (`AGILCalls.mount`), чат — свой чат-компонент | рекомендуется: один чат, звонок часть страницы |
| Telegram | бот присылает inline-кнопку/Web App с `embedUrl`, «Открыть звонок» | Web App ограничивает iframe; лучше открывать в новой вкладке/браузере |
| Slack | Block Kit с кнопкой-ссылкой на `joinUrl`, Slack App Home с iframe | Slack iframe ограничен CSP; ссылка надёжнее |
| Microsoft Teams | Adaptive Card с `openUrl` на `joinUrl`; вкладка (tab) с iframe | проверьте CSP вашего тенанта |
| Matrix / Element | Widget API с `embedUrl`, событие в комнату | матричные виджеты поддерживают iframe |
| Корпоративный портал | SDK inline + `chrome:'none'` | нативный вид, мини-окно общее |

## 5. Безопасность

- Токен звонка выдаёт бэкенд компании (`POST /v1/tokens` с `permissions`);
  API-ключ никогда не попадает в клиент мессенджера.
- 1:1: токен комнаты только для двух участников, `maxParticipants:2`, TTL
  токена; при утечке ссылки — `lock`/`kick`/истечение инвайта.
- Группы: гео/пароли/лобби — по политике тенанта; `accessPolicy` ограничивает
  запись/файлы/ассистента по ролям (гость/участник/модератор).
- Карточки звонка содержат только `joinUrl` с токеном ограниченного TTL; для
  чувствительных бесед — режим «только приглашённые» (waiting room).
- Запись/STT/AI — только с согласием и по политике тенанта; уведомление
  участникам (`session.recording.notifyParticipants`).

## 6. Рекомендуемые настройки тенанта для мессенджера

```jsonc
{
  "layout": { "chrome": "none", "mode": "spotlight", "minimized": { "enabled": true, "mode": "bubble" } },
  "session": {
    "chat": { "ui": "hidden" },                 // чат — мессенджерный
    "recording": { "consentRequired": true },
    "fileShare": { "enabled": true }
  },
  "providers": {
    "chat": { "mode": "external", "providerName": "corp-messenger", "endpoint": "https://chat.company/agil/chat", "apiKeyEnv": "AGIL_CHAT_PROVIDER_KEY", "fallback": "builtin" }
  },
  "features": { "chat": false, "knowledgeAgent": true, "recording": false }
}
```

## 7. Подводные камни

- **CSP/iframe:** мессенджеры часто запрещают iframe — используйте отдельную
  вкладку (`openInNewTab`) или SDK на своей странице.
- **Autoplay** в iframe требует user gesture — начинайте звонок по клику
  («Позвонить»), а не автоматически.
- **Уведомления о звонке** (входящий) — это сценарий мессенджера (push/call
  card); наш сервер даёт события, но не звонит на устройство (CallKit/Web Push
  — roadmap).
- **Групповые >8** — mesh не годится, нужен SFU (roadmap, LiveKit).
- **Мобильные вкладки** ограничивают одновременные камеры — для 1:1 хватает.
## Звонки только для участников корпоративного чата

1. Бэкенд компании проверяет сессию пользователя и получает состав чата из своего сервиса. Используйте внутренние стабильные ID участников длиной до 64 символов.
2. Создайте комнату через `POST /v1/rooms` с ключом организации в `x-api-key`. Например, тело запроса может быть `{"mode":"direct","allowedParticipantIds":["employee-42","employee-97"],"context":{"conversationId":"chat-203"}}`.
3. При входе пользователя вызовите `POST /v1/tokens` с тем же ключом и `{ "tenantId": "acme", "roomId": "…", "participant": { "name": "Алиса", "participantId": "employee-42", "role": "guest" }, "ttlSec": 300 }`. Назначайте `host` только по правилам компании. Отдайте выданный токен только этому пользователю.
4. В SDK передайте токен в `mountWidget` или встройте `embedUrl`, добавив токен участника. Сервер проверяет подпись, срок, комнату, организацию и ID при входе и подключении к WebSocket. Результат создания комнаты содержит ссылки без токена. Общие ссылки-приглашения для таких комнат отключены.

Список фиксируется при создании комнаты. Когда состав чата меняется, создайте новую комнату с актуальным списком и завершите прежнюю. Снимки Core сохраняют правило доступа при восстановлении. Комнаты, созданные без `allowedParticipantIds`, используют обычную политику входа.
