# Локализация интерфейса AgilFrame

Глоссарий, правила и список правок для пользовательской текстовой части продукта:
панель (`agil/core/apps/dashboard`), визуальный редактор (`agil/core/apps/editor`), виджет
(`agil/websdk/widget`), демо-страницы (`agil/websdk/demo`), вводный маркетинговый раздел
`README.md`.

Цель — чтобы нетехнический администратор понимал экран с первого прочтения.
Технические термины остаются только там, где без них нельзя (API, MCP, WebRTC,
TURN, OpenAPI, SFU), и при первом употреблении объясняются простыми словами.

## 1. Принципы

1. Коротко и конкретно: одна мысль — одно предложение.
2. Никакого сленга и жаргона: «протыкать», «заливать», «косяк», «рулит»,
   «тачка», «дебажить», «лагает» — запрещены.
3. Русское слово вместо английского, если оно есть: «копировать», «скачать»,
   «отправить», «комната», «участник», «запись», «расшифровка», «права».
4. Английский термин допустим, если это имя стандарта/протокола/продукта:
   API, MCP, WebRTC, TURN, SFU, OpenAPI, JSON, JWT, SDK, iframe, curl.
   При первом употреблении — короткое пояснение в скобках или подсказка.
5. Кнопки — глагол в инфинитиве: «Создать», «Сохранить», «Скачать»,
   «Копировать», «Повторить». Не «ОК», не «Далее →» без глагола.
6. Обращение — «вы» со строчной буквы в середине предложения; «Вы» — только
   в начале предложения.
7. Буква «ё» обязательна: «включён», «ещё», «зачёт», «подключён».
8. Кавычки — «ёлочки», тире — длинное (—), многоточие — один символ (…).
   Без «!!», «?!», «...» и дублей знаков.
9. Ошибка и пустое состояние отвечают на два вопроса: что случилось и что
   сделать. Где можно — дают ссылку или кнопку действия.
10. Смысл юридических и охранных текстов (согласие на запись, пароли,
    geo-политика, аудит) не меняем — только уточняем формулировки.

В редакторе названия разделов совпадают с пунктами левого меню; полное название
показывается во всплывающей подсказке, если пункт обрезан по ширине. Раздел базы
знаний в редакторе называется «База знаний» (коротко для меню), на панели —
«Ассистент знаний» / «Ассистент по базе знаний».

## 4. Решения и спорные места

Принято в этом проходе:

1. **«Тенант» → «организация»** во всём интерфейсе; в API-справочнике и JSON
   остаётся `tenant`. Требует подтверждения, что «организация» — принятый термин
   в тарифах и договорах.
2. **«AI» → «ИИ»**, «AI-агент» → «ИИ-агент». Названия моделей (DeepSeek) не
   трогали.
3. **«Knowledge-агент» → «Ассистент по базе знаний»** (в навигации — «Ассистент
   знаний»). В подзаголовке экрана осталась техническая сноска «В API этот
   раздел называется Knowledge-агент» — по ней QA находит экран.
4. **«Транскрипт» → «Расшифровка»**, вкладка комнаты тоже. Поле API `transcript`
   и файлы `.txt` не менялись.
5. **«Комплаенс» → «Соответствие правилам»**, «findings» → «замечания».
6. **embedded call, декоративная плашка.** Было `E2E POLICY · AUDIT ON`, стало
   «АУДИТ ВКЛЮЧЁН»: убрано утверждение о сквозном шифровании, которого продукт
   не гарантирует. Нужно подтверждение, что это допустимо для демо-страницы.
7. **QA-заблокированные строки.** «Настройки агента» (заголовок карточки базы
   знаний) оставлен, чтобы не ломать `agil/core/qa/ai/browser-dashboard-ai.mjs`; после
   обновления QA его стоит переименовать в «Настройки ассистента».
8. **Коды событий аудита** (`room.created — комната создана`, `lockout — …`)
   оставлены как значения API: по ним фильтруют журнал и сверяются с
   документацией. Русское пояснение стоит рядом.
9. **Технические имена в подсказках** (`tenantId`, `userId`, `roleId`,
   `session.chat.ui`, `config.features`, `x-api-key`) сохранены: по ним
   администратор сопоставляет интерфейс с конфигурацией и API.
10. **Значения перечислений** (`builtin/external/disabled`, `strict`,
    `mesh/sfu`, `host/moderator/guest`) не переименованы; русская подпись стоит
    рядом. Чтобы перевести сами пункты списков в редакторе, нужна доработка
    `renderSchema`/`selectField` — это изменение логики, не текста.
11. **Пресеты темы** Light/Dark/Corporate/Night/Minimal в редакторе оставлены
    названиями продуктовых тем (и их ищет QA регуляркой).
12. **Английский словарь виджета** (`en`) не менялся: правки только в русской
    локали.
13. **Юридические тексты** (согласие на запись, 152-ФЗ, пароли, geo-политика,
    ответственность за базу знаний) сохранены по смыслу.

Открытые вопросы для продукта:

1. «Организация» vs «тенант» в договорах и тарифах.
2. Показывать ли технические ключи (`session.chat.ui`, `features.*`) прямо в
   подписях или убрать их за «Подробнее».
3. Нужен ли отдельный термин для «внешнего сервиса» в тарифах (сейчас в UI —
   «внешний сервис», в API — `provider`).
4. Обновлять ли QA-скрипты под новые названия вкладок и кнопок (см. §6) или
   вернуть старые строки.
