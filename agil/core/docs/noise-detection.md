# Детекция шума в микрофоне

Локальная подсказка участнику: «слишком шумно». Фича не выполняет шумоподавление
и не отправляет аудио на сервер — это только анализ уровня/спектра на устройстве
и предупреждение в UI.

## 1. Флаг и доступ

| Что | Значение |
|---|---|
| Флаг | `features.noiseDetection` |
| По умолчанию | `false` (roadmap-фича, включается в конфиге тенанта) |
| Права | обычный `FeatureKey`; действует `security.accessPolicy` (роль/token/deny) |
| Виджет | монитор запускается только при `config.features.noiseDetection === true` **и** `canFeature(state, 'noiseDetection')` |
| Редактор/дашборд | подпись «Предупреждение о шуме» уже есть в метаданных фич |

При `false` виджет не создаёт `AudioContext`/`AnalyserNode`, не показывает тост и
не отправляет событие `noise-detected`. `updateConfig({ features: { noiseDetection:
false } })` останавливает уже запущенный монитор.

## 2. UX

Когда уровень шума превышает порог с учётом гистерезиса и cooldown, виджет:

1. отправляет host-событию `noise-detected` (payload без аудио — см. §5);
2. показывает warning-тост «Слишком шумно…» с действиями:
   - **«Выключить микрофон»** — `toggleMic(false)`;
   - **«Настроить»** — открывает панель настроек (выбор микрофона).

Повторное предупреждение — не чаще одного раза в 30–60 с на один и тот же трек.
Тост не блокирует звонок; при выключенном микрофоне предупреждений нет.

i18n-ключи (RU/EN): `noiseDetected`, `noiseMuteMic`, `noiseAdjust`.

## 3. Алгоритм

Реализация: `agil/websdk/widget/src/call/noise-detection.ts`.

### 3.1 Кадр

`NoiseMonitor` раз в 100 мс читает `AnalyserNode.fftSize = 1024` времени-доменных
сэмплов (`getFloatTimeDomainData`) с локального микрофонного трека. `AnalyserNode`
подключён только к источнику и **не подключён к `destination`** — это чисто
аналитическая ветка, которая не создаёт эха и не проигрывает звук.

`analyzeAudioFrame(samples, sampleRate)` — чистая функция, не бросает исключений
на пустых/`NaN`/`Infinity` буферах и не изменяет входной массив.

### 3.2 Признаки

| Признак | Как считается |
|---|---|
| `rms` | корень из среднего квадрата сэмплов кадра (линейная амплитуда 0..1) |
| `noiseFloor` | 10-й перцентиль RMS коротких окон (16 окон по ~64 сэмпла); устойчив к паузам речи |
| `spectralFlatness` | отношение геометрического и арифметического средних мощностей FFT в полосе 80 Гц–8 кГц, окно Ханна; 1 ≈ белый шум, ~0 ≈ тон/гармоники |
| `level` | `quiet` < 0.01 ≤ `low` < 0.035 ≤ `moderate` < 0.08 ≤ `high` (по `rms`) |

FFT — собственная итеративная radix-2 реализация (без внешних зависимостей).
Полоса анализа зависит от `sampleRate`, поэтому DC-смещение и сетевая наводка
ниже 80 Гц не «уплощают» спектр.

### 3.3 Порог и гистерезис

`noisy = rms ≥ 0.03 && noiseFloor ≥ 0.015 && spectralFlatness ≥ 0.35`.

Это отсекает:

- тишину/очень тихий фон (`rms` ниже порога);
- гармоническую речь: она громкая, но `spectralFlatness` у неё низкая, поэтому
  ложных срабатываний на голосе нет (проверено синтетическим гармоническим
  буфером);
- тон/гул/музыку с выраженной гармоникой (низкая плоскостность).

Гистерезис в `NoiseGate`:

- **вход**: 3 подряд «шумных» кадра (~300 мс);
- **выход**: 8 подряд «чистых» кадров (~800 мс);
- при `mute` счётчики сбрасываются;
- cooldown: по умолчанию 45 с, конфигурируется в диапазоне **30–60 с**
  (`resolveNoiseCooldownMs` жёстко клампит значение).

Пока шум сохраняется, после истечения cooldown допускается следующее
предупреждение; серия коротких шумовых всплесков внутри cooldown игнорируется.

## 4. Приватность

- Аудио, буферы и спектры **не покидают браузер**: нет `fetch`, WebSocket,
  записи или отправки на сервер.
- Наружу (в UI/host) уходит только событие `{ level, rms, at }`; сэмплов,
  частот и идентификаторов устройства в нём нет.
- `AnalyserNode` не подключён к выходу, поэтому мониторинг не слышен и не
  попадает в recording/transcription (они используют свои ветки).
- При выключенном флаге монитор не создаётся; при `dispose()` закрывается
  собственный `AudioContext` (общий контекст, переданный снаружи, не
  закрывается).

## 5. Публичное событие

```ts
const off = call.on('noise-detected', (payload) => {
  const { level, rms, at } = payload as AgilNoiseDetectedEvent;
  // level: 'quiet' | 'low' | 'moderate' | 'high'
  // rms:   линейный RMS кадра (0..1)
  // at:    epoch ms срабатывания
});
```

Событие типизировано в `AgilWidgetEventPayloads` и экспортируется как
`AgilNoiseDetectedEvent` из `@agil/calls-widget`. Headless-хост получает его тем же
`on('noise-detected')`; в default UI дополнительно показывается тост.

## 6. Жизненный цикл

`AgilWidgetSession.syncNoiseDetection()` создаёт ровно один `NoiseMonitor` на
активный `MediaStreamTrack` и останавливает его, когда:

- микрофон выключен (`settings.micEnabled === false`) или трек `enabled=false` /
  `muted=true`;
- пользователь вышел из звонка (`stopLocalMedia()`);
- сменил микрофон (`switchMicrophone()` сначала делает `dispose()`, затем
  запускает монитор на новом треке);
- флаг/права фичи выключены (`applyConfig()` / `updateConfig()`);
- трек завершился (`ended`) — монитор освобождает ресурсы сам.

`dispose()` очищает `setInterval`, снимает listener `ended`, отключает
`MediaStreamAudioSourceNode`/`AnalyserNode` и закрывает собственный
`AudioContext`. Повторный `dispose()` идемпотентен.

При выключении/включении микрофона или смене устройства монитор пересоздаётся,
поэтому cooldown начинается заново для нового трека (это защищает от накопления
устаревших предупреждений на старом устройстве).

## 7. Ограничения

- Это **не шумоподавление**: фича только предупреждает. Подавление шума — отдельный
  флаг `features.noiseSuppression` (constraints `getUserMedia`).
- Анализируется трек после DSP браузера (`noiseSuppression`, `autoGainControl`,
  `echoCancellation`). Если шумоподавление уже включено, фоновый шум может быть
  тише и детектор сработает позже/не сработает.
- Тональный шум (вентилятор/трансформатор/гул 50–60 Гц), музыка и отдельные
  голоса могут не распознаваться: у них низкая спектральная плоскостность.
  Это сознательный компромисс против ложных срабатываний на речи.
- Очень тихий широкополосный шум ниже `rms`-порога не считается проблемой.
- Порог не настраивается per-tenant через конфиг: значения зафиксированы в коде
  и покрыты тестами; менять их следует вместе с тестами синтетических буферов.
- Нет серверного анализа и облачных метрик: событие видит только host страницы.
- `AudioContext` может быть `suspended` до пользовательского жеста; вход в звонок
  или превью микрофона уже является жестом, поэтому на практике анализ стартует.
- В фоновой вкладке браузер может троттлить таймеры — предупреждение придёт с
  задержкой; это не влияет на сам звонок.

## 8. Тесты

`agil/websdk/widget/test/noise-detection.test.ts` (Node test runner, без DOM):

- синтетические буферы: тишина, белый шум, гармоническая «речь», тихий шип,
  тон 50 Гц;
- чистота `analyzeAudioFrame` и дегенеративные буферы;
- гистерезис 3/8, cooldown и его клампинг 30–60 с;
- `reset()` (смена устройства/новый звонок) снимает alert и начинает cooldown заново;
- mute: `NoiseGate.setMuted`, `track.enabled`, `track.muted`;
- `dispose()`: таймер, отключение tap, отсутствие поздних callback, `ended`;
- монитор не стартует на мёртвом треке.

Запуск:

```bash
npm test -w @agil/calls-widget
npm run typecheck -w @agil/calls-widget
npm run build -w @agil/calls-widget
```
