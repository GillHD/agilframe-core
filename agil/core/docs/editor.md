# Визуальный редактор панели AgilFrame (`agil/core/apps/editor`)

Vite-приложение для настройки `TenantConfig` тенанта: бренд, тема, фичи, лейаут,
аудио/видео, fallback, безопасность, доступы, AI- и knowledge-агент, интеграции и корпоративный вход (OIDC/SSO).
Слева — секции настроек, в центре — живое превью звонка в iframe, справа — JSON,
embed-сниппет, импорт/экспорт и сохранение в тенант.

Редактор **полностью работает офлайн**: при загрузке не делает ни одного сетевого
запроса, превью общается с iframe через `postMessage`, а сохранение в тенант — это
явное действие по кнопке.

Смежные документы: `agil/core/docs/extensibility.md` (заменяемые провайдеры возможностей),
`agil/core/docs/messenger.md` (звонки из корпоративного мессенджера, `mode`/`context` комнаты).

## Запуск и сборка

```bash
npm run dev -w @agil/editor        # http://localhost:5174/editor/ (dev, proxy /v1 → :8787)
npm run build -w @agil/editor      # dist/ → сервер раздаёт на /editor/
npm run typecheck -w @agil/editor
```

Прод-сборка кладётся в `agil/core/apps/editor/dist`, сервер (`@agil/calls-server`) раздаёт её
по `/editor/` (env `AGIL_EDITOR_DIR`). База Vite — `/editor/`, поэтому все ассеты
подтягиваются с префиксом.

Dev-прокси: `/v1` → `http://localhost:8787`, так что «Сохранить в тенант» можно
проверять в dev-режиме без CORS-настроек.

## Колонки

| Колонка | Что внутри |
|---|---|
| Слева | навигация по секциям + сами настройки (zod-схемы `@agil/protocol` → контролы) |
| Центр | iframe-превью + статус подключения, кнопки «открыть в новой вкладке», «обновить», выбор схемы light/dark/auto, лог событий |
| Справа | закреплённая панель сохранения («Сохранить в тенант» + статус), живой JSON конфига, копирование/скачивание, embed-сниппет, импорт, сброс, настройки server URL / tenantId / API-ключ |

Правая колонка прокручивается независимо от страницы, поэтому основное действие
вынесено в **sticky save dock** — панель вверху правой колонки, которая остаётся
видимой при прокрутке (desktop) и закрепляется внизу viewport на `≤1200px`
(`position: fixed`). Высота дока измеряется `ResizeObserver` (`--save-dock-height`),
`.app-body` получает `padding-bottom = высота дока + 28px`, а `html` —
`scroll-padding-bottom`, поэтому последняя секция/поле прокручиваются **выше** дока
и Tab-фокус не уходит под него. На мобильных/планшетах док **скрыт** (`is-offscreen`),
пока правая колонка не видна во viewport: он не перекрывает «Бренд», превью и другие
секции, и появляется при прокрутке к настройкам сохранения. Кнопка сохранения есть и
в доке, и в блоке настроек сервера — обе используют один `performSave()` и общий
статус (включая `success`/`error` от PATCH). Ссылка **«К настройкам»** (skip-link)
всегда видна в левом нижнем углу viewport (на мобильных — над save dock) и является
первым Tab-фокусом (`outline` 2px, ведёт к `#fields`).

Шапка: переключатель светлой/тёмной темы редактора (сохраняется в
`localStorage`), индикатор черновика, tenant-pill и ссылки **API docs** →
`<base>/docs` (человеческий explorer), **OpenAPI JSON** →
`<base>/openapi.json` (машиночитаемая спецификация для Swagger/Postman/кодогенерации;
title это явно поясняет), **API guide** → `<base>/docs/api-guide.md`, **API.md** →
`<base>/docs/api.md` (все открываются в новой вкладке; `rel="noopener noreferrer"`).
`<base>`: на localhost — `AGIL_SERVER_URL`/`http://localhost:8787`; на проде, если явный
нелокальный server URL не задан — `window.location.origin` (сервер раздаёт `/docs` и
`/openapi.json` сам). Так ссылки не уводят на `localhost:8787` в проде (F-07).

На `≤1100px` шапка — **одна строка**: скрыты подзаголовок бренда, draft/tenant-pill,
meta-полоса с ссылками горизонтально прокручивается; переключатель темы вынесен из
неё и всегда виден справа (`#theme-toggle` 40×40). На `≤720px` ссылки показывают
короткие подписи из `data-short` (**API / OpenAPI / Guide / API.md**) — все четыре
видны на 390 без обрезки, полные названия остаются в `title`/ARIA; на `≤420px`
скрывается текст бренда, «К настройкам» становится иконкой в шапке. Высота шапки —
60px на 390/768/1440, горизонтального overflow страницы нет (`scrollWidth = 390`).

На мобильных (`≤720px`) навигация секций — горизонтальная скролл-полоса (не 16 рядов),
а карточки полей — **аккордеон**: первая карточка раскрыта, остальные свёрнуты;
все поля сохраняются и раскрываются кнопкой 40×40 (`card-toggle`), поэтому страница
секции занимает ~3–5 тыс. px вместо 4,5–10 тыс. Тап-таргеты — ≥40px (переключатели
46×40, кнопки/селекты 40), компактными остаются только chips.

## Секции

1. **Бренд** — productName, organizationName, logoUrl/logoHeightPx, supportUrl,
   footerText, faviconUrl; бренд-цвет → `generatePalette` + предпросмотр палитры и
   кнопка «Применить к теме»; 5 пресетов (`light`, `dark`, `corporate`, `night`, `minimal`).
2. **Тема** — scheme, все 36 цветовых токенов с color-picker и бейджем контраста
   (`auditTheme`), панель accessibility, typography, shape, spacing,
   **галерея фонов** (6 локальных пейзажей + загрузка своего изображения, см.
   «Фон комнаты: пресеты и загрузка» ниже), поля background, logo, motion.
3. **Фичи** — все флаги `features`; roadmap-флаги с бейджем «roadmap», бета — «beta»,
   счётчик включённого.
4. **Доступы** (§18) — режим `role-defaults`/`strict`, матрица «роль × функция»
   (host/moderator/guest), `deniedFeatures`, таблица `userOverrides` (userId + набор
   фич), живой расчёт effective через `resolveAccess` и доступность knowledge-агента
   через `resolveKnowledgeAgentAccess`. Блок **«Свои роли» (customRoles)**:
   таблица id/name/description/baseRole/features/canModerate/color, добавление и
   удаление строк, features — мультивыбор; live-проверка id (lowercase latin/digits/_/-),
   зарезервированных id (host/moderator/guest/anonymous/system/admin), дубликатов,
   лимита 30, пустых features и `baseRole=guest`+recording; подсказка «встроенные
   роли не удаляются, их права меняются в матрице»; всё в JSON-экспорте. Полное
   руководство: `agil/core/docs/api-guide.md` §3.
5. **Лейаут** — mode/selfView/controlsPosition/chatPosition/chatDefaultOpen,
   show*-флаги, tileAspectRatio, gridMaxTiles, spotlightFollowSpeaker; §22 —
   `chrome` (full/compact/none), **`header`** (full/compact/hidden — плотность шапки
   звонка), **`videoFit`** (contain/cover — как видео заполняет плитку),
   **`immersiveVideo`** (медиа на весь контейнер, шапка/контролы поверх),
   `minimized` (bar/bubble, позиция, self-view,
   контролы), `persistAcrossPages` (+ `AGILCalls.resume()`), `inheritHostStyles`,
   а также «Чат и встраивание»: `session.chat.ui` (builtin/external/hidden),
   `externalProviderName`, `allowHostInjection`, `allowSystemMessages` с
   пояснениями («external — чат компании, виджет только передаёт события»,
   «none — без шапки, как часть страницы», «persistAcrossPages — resume после
   навигации»).
6. **Аудио/видео** — кодеки (мультивыбор + preferred), simulcast/SVC,
   resolution/fps/bitrate/degradationPreference/keyFrameInterval/contentHint;
   audio codecs/dtx/ptime/opusBitrate/jitterBuffer. Блок **«Кодирование»**
   (`TenantConfig.video.encoding`): стратегия `auto` / `prefer-hardware` /
   `software-only` (сначала уже поддерживаемый камерой/браузером кодек, затем
   аппаратный энкодер, затем программный), упорядоченный список
   `preferredCodecs` (AV1/H.264/VP9/VP8, приоритет меняется стрелками, порядок
   сохраняется в JSON) и `allowH265` с предупреждением **«H.265 не поддерживается
   WebRTC»** при включении. Сервер в обычных звонках не транскодирует — только
   пересылает медиа (см. также «Обработка медиа»). Блок **«Обработка медиа»**
   (`TenantConfig.mediaProcessing`): режим `client-only` (по умолчанию — всё в
   браузере, сервер только пересылает медиа) / `server-assisted` (нужны CPU/GPU и
   воркеры, выше задержка и стоимость), тумблеры server video/audio, egress
   (облачная запись отдельным воркером), transcoding (SFU пересылает без
   транскодинга) и провайдер `none|livekit-egress|external`. При включении —
   предупреждения: несоответствие `client-only` и серверных шагов, ресурсы/стоимость,
   `provider=none` при egress, дорогой transcoding; по умолчанию — информационное
   пояснение о клиентской обработке. Все поля входят в JSON-экспорт/PATCH.
7. **Fallback** — lowBandwidth: enabled/strategy/пороги enter/restore/autoReconnect/iceRestart.
8. **Безопасность** — requireToken/waitingRoom/lock/moderatorJoinFirst, пароль
   (тумблер `passwordRequired` + подсказка, что пароль задаётся при создании
   комнаты и хранится только scrypt-хэшем), lockout, geo (allowed/blocked страны
   ISO-3166 alpha-2, VPN), media integrity и аудит.
9. **Knowledge-агент** (§18) — enabled/endpoint/apiKeyEnv/timeoutMs/allowedRoles/
   requirePermission/citations/maxAnswerChars/systemPrompt/denyMessage + предпросмотр
   «кто может спросить» по ролям.
10. **Сессия** — locale, blur/фоны, join-предпочтения, recording, transcription,
    fileShare, screenShare.
11. **AI-агент** — session.aiAgent + таблица `policyRules` (id/name/type/pattern/
    severity/action/enabled, добавить/удалить).
12. **Интеграции** (§19) — allowedOrigins (домены для встраивания), embedPostMessage
    и вебхуки (url, events, secretEnv, retries, timeoutMs, enabled) + предупреждения
    (только HTTPS, выключенный вебхук). Вход через IdP вынесен в отдельную секцию
    «Корпоративный вход».
13. **Корпоративный вход** (§19/SSO) — `integrations.identity`: mode oidc/token,
    issuer, audience, jwksUrl и claim-маппинг (userId/name/role/permissions/verified);
    `security.requireVerifiedIdentity`. Предупреждения: без IdP вход гостевой,
    OIDC обязан заполнить issuer/audience/jwksUrl, а SSO-токен проверяется на
    сервере (JWKS/issuer/audience); включение requireVerifiedIdentity без OIDC
    блокирует вход. Поля входят в JSON/PATCH.
14. **Комната и лимиты** — room.name/welcomeMessage/waitingMessage/soundOnJoinLeave.
    Опубликуйте имя комнаты, приветствие и сообщение зала ожидания в настройках
    организации. Приветствие видно на форме входа и сразу после подключения.
    Сообщение зала видно, пока организатор рассматривает заявку. Для отдельной
    комнаты его можно изменить через `configOverrides.room.waitingMessage`.
    При пустом тексте используется стандартная фраза на языке интерфейса.
    Переключатель «Звук входа/выхода» управляет короткими уведомлениями о
    подключении и выходе других участников. Виджет использует устройство,
    выбранное в настройках звонка. При автоматическом входе браузер может
    разрешить звук после первого взаимодействия со страницей.
    В этом же разделе настраиваются `limits.maxParticipants`,
    `limits.maxDurationMin` и `limits.maxVideoSubscriptions`. Лимит участников
    задаёт число мест по умолчанию для новых групповых комнат. Настройки
    масштабирования, профиль SFU и тариф могут его уменьшить. Для видеоподписок
    применяется меньшее значение из разделов «Комната» и «Масштабирование».
    Поле «Видео в галерее» задаёт фиксированный бюджет. Очистите его и
    опубликуйте настройки, чтобы вернуть расчёт по профилю. Если задан
    `scale.maxVisibleVideos`, после очистки применяется это значение.
    Максимальная длительность отсчитывается от первого подключения к Core.
    Срок фиксируется на время встречи и сохраняется при перезапуске Core.
    По истечении срока Core закрывает встречу и её подкомнаты. Для закрытия
    комнаты на LiveKit на сервере задаются `AGIL_SFU_URL`, `AGIL_SFU_API_KEY`
    и `AGIL_SFU_API_SECRET`. Токен подключения к медиасерверу ограничен
    сроком встречи. [Операция LiveKit](https://docs.livekit.io/reference/other/roomservice-api/#deleteroom).
    В блоке
    «Тестовая комната (контекст мессенджера)» можно задать `mode` (direct/group), `transport`
    для direct (P2P/SFU/не задан) и `context` (messenger/conversationId/
    directPeerId/title) — опционально, для тестовых комнат; поля не входят в
    `TenantConfig` (реальные комнаты создаются через `POST /v1/admin/rooms`),
    кнопка копирует готовый JSON-запрос. `direct` = 1:1 звонок из мессенджера,
    `maxParticipants: 2`; `transport:'p2p'` даёт mesh/2 без серверного медиа,
    `transport:'sfu'` и пустое поле используют текущий режим организации.
    Поля транспорта и собеседника доступны для личного звонка. Core
    отклоняет запись через сервер, трансляцию и вебинар в режиме P2P с кодом 409.
    Получив ID созданной комнаты, введите его в блоке **«Тестовый токен (roleId)»**.
    Выберите роль из раздела «Доступы» и скопируйте JSON для `POST /v1/tokens`.
    Запрос содержит ID комнаты, `participant.roleId` и базовую роль выбранной записи.
    Сценарий: `agil/core/docs/messenger.md`, права ролей — `agil/core/docs/api-guide.md` §3.
15. **Провайдеры** (§23) — 6 карточек заменяемых возможностей (chat/files/stt/
    notifications/recording/backgrounds): `mode` builtin/external/disabled,
    providerName, endpoint (валидация http(s) с ошибкой под полем), apiKeyEnv
    (только имя env-переменной), timeoutMs, fallback builtin/fail, options JSON
    (с валидацией). Подсказки «по умолчанию встроено; external — система
    компании»; сводка предупреждений (external без endpoint/apiKeyEnv, не-HTTPS,
    fallback=fail, disabled при включённой фиче). Сохраняется в
    `config.providers` через «Сохранить в тенант» (PATCH). Полное руководство:
    `agil/core/docs/extensibility.md`.
16. **In-call ассистент** — `session.inCallAgent`: enabled, mode
    (local/external/hybrid), endpoint, apiKeyEnv, timeoutMs, systemPrompt, model,
    spotlight, maxActionsPerReply, audit, denyMessage; multiselect `allowedTools`
    (18 инструментов) с бейджами требуемых фич/ролей; пояснения «агент действует
    только с правами пользователя; local работает офлайн», «spotlight — подсветка
    кнопок», «external — LLM компании через HMAC». Конфиг сохраняется обычным
    PATCH; в MCP — `agil_get_assistant_tools` / `agil_explain_spotlight` /
    `agil_explain_feature`; сценарий: `agil/core/docs/in-call-agent.md`,
    `agil/core/docs/llm-integrations.md`.
17. **Масштабирование и стриминг** — `TenantConfig.scale`: mediaMode
    (mesh/sfu/broadcast), maxParticipants (2..50000), maxVideoSubscriptions;
    сигналинг (nodeId/redisUrl/pubsubChannel/stickySessions + таблица узлов);
    SFU (provider/url/apiKeyEnv/apiSecretEnv/region/maxParticipants); TURN-пул
    (таблица id/urls/username/credentialEnv/region/weight); балансировщик
    (strategy/healthPath/stickyCookie); вебинар (enabled/hostOnlyPublish/
    viewerLimit/chatMode/reactions/raiseHandQueue); стриминг (enabled/provider/
    rtmpUrl/hlsUrl/latencyMode) и CDN. Live-проверка предупреждений (mesh при
    больших лимитах, sfu без url, TURN без credentialEnv, webinar без broadcast,
    несколько узлов без Redis, streaming без provider, CDN без baseUrl);
    URL-валидация и правило «секреты — только имена env-переменных»; всё уходит
    в JSON-экспорт и сохраняется обычным PATCH. Гайд: `agil/core/docs/scaling.md` §4–§9.

## Фон комнаты: пресеты и загрузка

Блок **«Галерея фонов»** в секции «Тема» (сразу перед полями `theme.background`):

- **6 пейзажей** — SVG-файлы в `agil/core/apps/editor/src/backgrounds/*.svg`
  (альпийский рассвет, лесное озеро, дюны на закате, северное сияние, туманные
  холмы, морской горизонт). Файлы лежат в репозитории и импортируются как
  `?raw`; внешних ссылок и сетевых запросов нет. Каждый пресет отдаётся
  percent-encoded `data:image/svg+xml` (≈3–5 КБ) и применяется одним кликом:
  `theme.background = { type: 'image', imageUrl: <data URL>, imagePosition:
  'cover', gradient: <подходящий CSS-градиент> }`. Градиент — запасной фон, если
  браузер не отрисует SVG.
- **«Без изображения»** — возвращает `type: 'solid'`, `imageUrl: ''` (цвет или
  градиент из полей ниже). **«Убрать фон»** делает то же самое и удаляет
  закэшированную копию своего изображения.
- **«Загрузить изображение»** — выбор JPEG, PNG, WebP, AVIF или GIF объёмом до 20 МБ.
  SVG отклоняется: вектор может содержать активное содержимое. Картинка
  декодируется через `createImageBitmap` (fallback `<img>`), масштабируется до
  **1280 px по длинной стороне** и кодируется в WebP (fallback JPEG) с
  прогрессивным снижением качества/размера, пока data URL не уложится в
  бюджет. Прозрачность подложки заменяется белым — фоны видео непрозрачные.
  Готовое изображение попадает в `theme.background.imageUrl` как data URL,
  поэтому работает в превью, в экспорте и в виджете на любом хосте.
- **«Недавние изображения»** возвращают загруженный фон после выбора пресета или перезагрузки редактора. Список доступен в том же профиле браузера.

### Кэш и приватность

- Сжатое изображение кэшируется **только в браузере**: IndexedDB `agil-editor`,
  store `backgrounds` (ключ `id`, хранится data URL, имя, mime, размеры,
  `createdAt`; хранятся до **6** последних загрузок, старые вытесняются). При
  недоступности IndexedDB (приватный режим, отключённые сторонние данные)
  используется localStorage-слот `agil.editor.backgrounds.v1` с бюджетом
  **2 МБ** и максимум 3 записями; старые записи вытесняются. Если недоступны
  оба хранилища — изображение всё равно попадает в конфигурацию, теряется
  только кэш (галерея сообщает об этом тостом).
- Файл **никуда не загружается** при выборе: чтение, сжатие и запись в кэш
  локальные. На сервер он уходит только вместе с конфигурацией по явной кнопке
  «Сохранить в организации» (data URL внутри JSON). Внешних запросов за
  пресетами/картинками нет.
- Черновик редактора (`localStorage`, ключ `agil.editor.draft.v1`) тоже содержит
  data URL, то есть изображение сохраняется в этом браузере до сброса/очистки.
  «Убрать фон» удаляет кэшированную копию, но data URL может остаться в старом
  черновике до следующего автосохранения.
- **Лимит конфигурации.** Сервер принимает JSON-тело до **1 МиБ**
  (`JSON_BODY_LIMIT`). Загрузка ограничена `MAX_BACKGROUND_DATA_URL_CHARS =
  700 000` символов, а перед применением редактор проверяет сериализованный
  конфиг (`MAX_CONFIG_CHARS = 900 000`): при переполнении показывает ошибку и
  не меняет фон. В карточке JSON видно «N КБ из 1 МБ»; при приближении к лимиту
  подпись подсвечивается. Base64-кодирование увеличивает размер картинки
  примерно на 33 %, поэтому 1280 px WebP обычно даёт 60–250 КБ.
- **Ограничения.** Квота localStorage/IndexedDB зависит от браузера и режима
  (в приватном окне обычно 0); лимит 1280 px может быть мал для 4K-мониторов;
  data URL увеличивает экспортируемый JSON и PATCH-запрос; при очень плотном
  фото сжатие останавливается на 640 px / q0.5, и если бюджет всё равно
  превышен — загрузка отклоняется с понятным сообщением.

Проверка: `agil/core/qa/background-presets/capture.mjs` (24 проверки,
13 скриншотов, `data/report.json`) — галерея, загрузка реального файла,
IndexedDB, превью, размер конфига, светлая тема виджета/embed, типографика
(нет текста < 12 px) и скроллбары редактора/виджета/дашборда.

## Превью: iframe-контракт

Превью показывает **реальную комнату**, иначе вход в звонок давал «Room not found».
Перед монтированием iframe редактор создаёт одноразовую комнату через публичный API:

```http
POST {serverUrl}/v1/rooms
content-type: application/json

{ "tenantId": "<tenantId>", "name": "Превью редактора" }
```

→ `{ room: { id }, token, expiresAt }`; в iframe подставляется
`/embed.html?room=<id>&token=<token>&tenant=<tenantId>&_r=<cache-bust>`. Токен
живёт **только в URL same-origin iframe**: он не попадает в UI, лог событий, загрузки
или адресную строку «Новая вкладка» (там URL без токена). Сессия кэшируется до смены
tenant/server, пересоздаётся при истечении `expiresAt` (обновление за минуту до TTL) и
по кнопке «Обновить». Смена tenant/сервера пересоздаёт комнату и перезагружает iframe;
изменения конфига/темы применяются через `postMessage` без пересоздания комнаты.

Если `POST /v1/rooms` недоступен (анонимные комнаты выключены, 401/403/404/сеть),
iframe получает fallback `?room=preview&tenant=<tenantId>&previewMode=1`. Редактор
инжектит в same-origin iframe баннер **«Это превью темы, чтобы проверить звонок,
создайте комнату»** и блокирует вход: кнопки «Войти в звонок»/«Только слушать»
disabled, submit/клики перехватываются — ложного `Room not found` не возникает.
Если iframe cross-origin (dev-демо на другом порту), инжект невозможен — остаётся
параметр `previewMode=1` для нативной поддержки в embed.

Базовый embed URL: `VITE_PREVIEW_URL` (если задан), иначе dev
`http://localhost:5173/embed.html`, иначе same-origin `<location.origin>/embed.html`
(сервер раздаёт demo в корне, редактор — под `/editor/`). «Новая вкладка» открывает
отдельный предпросмотр в редакторе. Перед открытием текущий черновик записывается
в браузер. В новой вкладке применяются его оформление и выбранный тест-сценарий,
а адрес вкладки содержит только параметры редактора.

Если iframe не отвечает (`agil:ready` не пришёл за ~3.2 с), показывается
offline-overlay «preview offline — JSON/export work» с подсказкой (dev: `npm run dev`;
prod: проверить, что сервер раздаёт `/embed.html`, или задать `VITE_PREVIEW_URL`).
На работающем проде overlay не появляется: iframe подключается и присылает
`agil:ready`.

На каждое изменение конфига (debounce 150 мс) редактор отправляет в iframe:

```js
iframe.contentWindow.postMessage({ type: 'agil:config', config }, '*');
// отдельно при смене темы/схемы:
iframe.contentWindow.postMessage({ type: 'agil:theme', theme }, '*');
iframe.contentWindow.postMessage({ type: 'agil:scheme', scheme }, '*');
```

Слушает сообщения из iframe (по контракту §7):

- `{type:'agil:ready', capabilities}` — статус «превью подключено»;
- `{type:'agil:event', event, payload}` — лог событий;
- `{type:'agil:state', state}` — участники/качество/connectionState (статус);
- `{type:'agil:chat', message}` — лог чата.

§22: если в конфиге `session.chat.ui = 'external'`, редактор показывает пояснение,
что чат компании получает события `agil:chat` и отвечает через `agil:chat-send` /
`sendChat()`; при `hidden` чат полностью выключен. Для `minimized`/`persistAcrossPages`
в экспортируемом сниппете используется `config.layout` и `AGILCalls.resume()`.

Если демо не запущено, редактор остаётся работоспособным: статус `preview offline`,
все настройки, JSON и экспорт работают локально.

Кнопки над превью: «Открыть в новой вкладке», «Обновить превью», селектор схемы
`light/dark/auto` (пишет `theme.scheme` в конфиг и отправляет `agil:scheme`).

Смена схемы не просто меняет флаг: редактор пересобирает палитру
(`src/theme-scheme.ts`, тот же алгоритм, что `themeForScheme` виджета) из пресета
целевой схемы, сохраняя бренд-primary/accent, типографику, shape/spacing, логотип и
фон. Без этого «светлая» схема оставляла тёмные токены — белый текст на светлом фоне
(naive QA 5.9). Нормализация выполняется и в store (экспорт/PATCH), и перед
`postMessage` в превью. Проверка контраста в iframe: в light и dark все текстовые
элементы join-screen имеют ≥4.5:1 (после фикса виджетной подсказки в
`@agil/calls-widget`); минимум — 5.00:1 (light), 6.38:1 (dark). См. `agil/core/docs/qa-editor.md` §8.2.

## Загрузка и сохранение настроек организации

Правая панель, блок настроек сервера:

- **Адрес сервера** — по умолчанию адрес развернутой системы, при локальной разработке `http://localhost:8787`.
- **Идентификатор организации** — назначение для загрузки и публикации. Его видно рядом с кнопкой сохранения.
- **API-ключ** — ключ указанной организации. Редактор хранит его в `sessionStorage` текущей вкладки.

Нажмите «Загрузить из организации», чтобы получить конфигурацию через `GET /v1/tenants/{tenantId}/config`. Ключ для чтения не отправляется. Если загруженные настройки отличаются от черновика, редактор попросит подтвердить замену. Отмена сохраняет черновик. Если изменить адрес, организацию или черновик во время запроса, загрузку нужно повторить.

Кнопка «Сохранить в организации» записывает черновик. Для публикации черновика в другой организации нужно подтвердить выбранное назначение.

```http
PATCH {serverUrl}/v1/tenants/{tenantId}/config
content-type: application/json
x-api-key: {apiKey}

{ ...полный TenantConfig }
```

Ответ `{config, etag}` подтверждает публикацию. Редактор показывает, в какой организации сохранились настройки. Ошибки показываются
человеческим текстом: недоступный сервер (подсказка запустить `npm run dev`),
400 (сервер отклонил значения), 401/403 (проверьте ключ/тенант), 404, 5xx,
таймаут 8 с. Редактор валидирует конфиг локально перед отправкой.

## Маскот-помощник «Agil»

В редакторе есть тот же помощник, что и в панели (одинаковые ассеты, жесты и кнопки):
плавающая кнопка снизу справа (58px, на мобильных 44px, safe-area), перетаскиваемая
мышью/тачем (позиция в `localStorage`), с idle-анимацией `wave` и состояниями
`thinking` / `thumbsup` / `alert` / `angry` / `celebrate`. Пока панель ассистента
открыта, FAB **скрыт**; закрытие по «×» или **Escape** возвращает его. Имя по
умолчанию — **Agil**; старые конфиги/черновики с `branding.mascotName = "Аги"`
мигрируются в `Agil` при загрузке и импорте (пользовательские имена не перетираются).

- **Ассеты**: анимированные WebP `/branding/mascot/animated/mascot-<expr>.webp`
  с корня origin (как отдаёт сервер/demo); если их нет — резервные копии из
  `agil/core/apps/editor/public/branding/mascot/**` (`/editor/branding/...`), затем статичные
  PNG и inline-инициалы. Всё работает и при выключенном сервере.
- **Роль по местоположению**: при переходе по разделам панель автоматически
  выбирает одну из 7 ролей и показывает её в свёрнутом заголовке «Настройки
  помощника и примеры» (можно сменить вручную — до следующей смены раздела):

| Раздел редактора | Роль |
|---|---|
| Бренд, Тема, Лейаут, Функции, Аудио/видео, Fallback | `config-guardian` |
| Доступы | `roles-admin` |
| Безопасность, Корпоративный вход | `security-reviewer` |
| Интеграции, Провайдеры (вебхуки) | `api-helper` |
| Масштабирование | `scaling-advisor` |
| AI-агент, Knowledge-агент, In-call ассистент | `config-guardian` |
| Комната, Сессия | `onboarding` |

- **Чат**: `POST /v1/admin/assistant` с `x-api-key` (из настроек сохранения),
  `role` и `context` `{screen, tenantId, currentConfig, chatId, memory?}`. `chatId`
  — текущая сессия; `memory` — релевантные фрагменты **других** чатов (≤2000
  символов, поиск по словам с лёгким стеммингом), чтобы помощник помнил прошлые
  обсуждения и не выдумывал факты. Ответ показывает reply, при `fallback:true`
  (нет DeepSeek-ключа) — бейдж **«локальный режим»** и тег «локально». При
  404/401/сети редактор отвечает детерминированным локальным fallback по роли.

- **История чатов**: сессии хранятся в `localStorage`
  (`agil.editor.mascot.chats.v2`, старая `...history.v1` мигрирует в первую
  сессию). Кнопка «История» открывает drawer: авто-заголовок (по первому вопросу),
  дата, поиск по названию/тексту, открыть, переименовать, удалить и «Новый чат»;
  после перезагрузки восстанавливается активная сессия. Кнопка «Новый чат» есть и
  в шапке.
- **Компактность**: роль/стартеры/примеры упакованы в сворачиваемый блок
  «Настройки помощника и примеры» и автоматически сворачиваются после первого
  сообщения; suggestions показываются только в пустом чате; сообщения — основной
  скролл, composer закреплён внизу, увеличены line-height/контраст.
- **Guard перед сохранением**: кнопка «Сохранить в тенант» сначала вызывает
  `POST /v1/admin/guard/assess` `{kind:'config', next: config, intent}`; если
  `requiresConfirmation` — открывается блокирующая модалка с маскотом `alert`/
  `angry`, risk-бейджем, findings (`title`, `description`, `impact`, `affected`),
  рекомендациями и обязательным чекбоксом **«Я понимаю последствия»**. Кнопка
  «Всё равно сохранить» активна только после чекбокса; **«Отмена»/Escape не
  выполняют PATCH** (статус «Сохранение отменено»). Если guard-endpoint недоступен
  (404/401/сеть), строится консервативная локальная оценка (опасные изменения
  features, ограничивающие доступы, внешние провайдеры, http-вебхуки, выключенный
  маскот) с бейджем «проверка без сервера» и тем же чекбоксом.
- **Брендинг**: имя, включённость (`branding.mascotEnabled`), свой `mascotUrl` и
  набор `branding.mascotExpressions` читаются из конфига и обновляются на любое
  изменение бренда (в т.ч. после импорта/сохранения). `mascotEnabled=false`
  скрывает FAB и панель; битый URL уходит в inline-fallback.
- **Мобильный 390**: панель — full-screen overlay (`100dvh`), компактная шапка
  (высота ~49px), FAB скрыт при открытой панели и стоит над закреплённой панелью
  сохранения (bottom 128px + safe-area), не перекрывая «Сохранить в тенант»; при
  фокусе в любое поле ввода FAB скрывается.

## Тест-сценарий: дизайн-превью с N участниками

В тулбаре превью — панель **«Тест-сценарий»** (`details`): количество участников
**1–50** (number + slider, дефолт 2), раскладка `grid`/`spotlight`, стиль контролов
`bar`/`island`/`minimal`, кнопки «Применить»/«Сбросить». Количество и раскладка
сохраняются в браузере отдельно для каждой организации. «Сбросить» возвращает
двух участников и раскладку «Сетка», сохраняя стиль панели из черновика.

Там же — layout-переключатели **`header`** (full/compact/hidden), **`videoFit`**
(contain/cover) и чекбокс **«Видео на весь интерфейс (immersive)»**. Они меняют
реальные поля `TenantConfig.layout` (те же, что в секции «Лейаут»), сохраняются/
PATCH-ятся как обычный конфиг и мгновенно уходят в превью сообщением
`{type:'agil:config', config, replace:true}` — без перезагрузки iframe. Стиль контролов
дополнительно пишется в `layout.controlsStyle`.

Сценарии 25/50 участников проверены с immersive: сетка заполняет весь контейнер
виджета (682×630 на 1440, 368×437 на 390), шапка `compact`/`hidden` — absolute
overlay (hidden: opacity 0 с появлением по hover/focus), контролы `island`/`minimal`
— absolute overlay поверх видео, horizontal overflow страницы/виджета отсутствует.
Скриншоты: `agil/core/qa/editor/screens/sim-immersive-*.png`; метрики —
`agil/core/qa/editor/artifacts/simulation-immersive-verify.json`.

После `agil:ready` редактор отправляет в same-origin iframe (URL всегда содержит
`preview=1`, без него виджет отвечает `reason:"preview-required"`):

```js
iframe.contentWindow.postMessage({
  type: 'agil:simulate-participants',
  count, layout, controls, requestId,
}, location.origin);
```

iframe отвечает `{type:'agil:simulate-participants-ack', ok:true, requestId, count,
layout, controls}`; изменения count/раскладки/контролов применяются **без
перезагрузки** (auto-send с debounce 250 мс + «Применить»). Если ack не пришёл за
1.5 с (старый сервер/виджет) — статус «сервер/виджет не поддерживает симуляцию»,
без создания реальных комнат/WS-ботов. Симуляция полностью синтетическая: участники
без peer connections/WS/комнат, счётчик и плитки обновляются в UI, реальные данные
не затрагиваются. При уже подключённом `self` виджет трактует `count` как **всего
участников сцены** (включая self) — плиток ровно N.

Под превью показывается подпись **«Тестовые участники: N (дизайн-превью, не реальные
люди)»**; при fallback/неподдержке она остаётся, а причина пишется в статус панели.
Проверено 1/2/9/25/50 на 1440/390: плитки=N, счётчик=N, participants panel N строк,
без overflow и лагов (ack ~0.4 с, DOM до ~2.4k узлов), `Reset` возвращает дефолт 2.
Скриншоты: `agil/core/qa/editor/screens/mascot/sim-*.png`; метрики —
`agil/core/qa/editor/artifacts/simulation-verify.json`.

## Экспорт / импорт

- **JSON** — текущий черновик. Кнопки «Копировать JSON» и «Скачать JSON» сохраняют его целиком.
- **Код для встраивания** — HTML с `<script src="{serverUrl}/sdk/agil-calls.js">` и
  `AGILCalls.mount('#agil-call', {room, serverUrl, tenantId, theme:{scheme}})`; копируется
  одной кнопкой.
- **Импорт** — вставьте JSON или выберите файл. Полный экспорт заменяет черновик, частичный JSON меняет указанные в нём поля. Если JSON содержит ошибки, редактор показывает путь к полю и причину. Организацию для публикации задаёт поле «Идентификатор организации».
- **Сброс** — после подтверждения редактор возвращает черновик к исходным настройкам. Для записи изменений на сервер нажмите «Сохранить в организации».

Во время сохранения проверяется версия черновика на момент нажатия. Если она изменилась до окончания проверки, нажмите «Сохранить в организации» ещё раз.

Черновик автоматически сохраняется в `localStorage` (последние правки переживают
перезагрузку страницы); есть кнопка сброса.

## Безопасность

- Никаких внешних UI-библиотек и CDN: всё локально, включая иконки (inline SVG sprite).
- Конфигурация организации загружается и публикуется по соответствующим кнопкам. Предпросмотр подключается к отдельной тестовой комнате.
- API-ключ не попадает в DOM-лог, не пишется в консоль и не включается в JSON/сниппет.
- JSON-импорт и embed-сниппет экранируются; недоверенный JSON валидируется zod до
  применения к состоянию.
- `postMessage` отправляется в `'*'` (MVP-контракт §7); для продакшена ограничьте
  origin через `VITE_PREVIEW_URL`/сервер.
