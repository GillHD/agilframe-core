# Whiteboard и пометки на демонстрации экрана (P2)

Опциональный слой совместной работы: доска для рисования и аннотации поверх
демонстрации экрана. Обе фичи **выключены по умолчанию** и включаются флагами
тенанта `features.whiteboard` / `features.annotations`; сервер и виджет
применяют один и тот же гейт (конфиг + эффективные права участника).

- Протокол: `agil/core/packages/protocol/src/whiteboard.ts`,
  сообщения — `agil/core/packages/protocol/src/signaling.ts`.
- Сервер: `agil/core/apps/server/src/whiteboard.ts` (per-room state),
  WS-обработчики — `agil/core/apps/server/src/signaling.ts`.
- Виджет: `agil/websdk/widget/src/call/whiteboard.ts` (headless-модель),
  `ui/whiteboard-panel.ts`, `ui/annotation-overlay.ts`,
  `ui/stroke-toolbar.ts`, `ui/whiteboard-canvas.ts`.
- API: раздел 36 в [api.md](api.md).

## 1. Включение

```bash
# Полный PUT конфига тенанта (или PATCH с тем же деревом features)
curl -X PUT http://localhost:8787/v1/tenants/demo/config \
  -H 'x-api-key: dev-key' -H 'content-type: application/json' \
  -d '{"features":{"whiteboard":true,"annotations":true}, ...остальной конфиг...}'
```

В dashboard/editor флаги называются «Доска» и «Пометки на экране». Права
проверяются по обычной модели доступа (`security.accessPolicy`): host и
moderator получают фичу при включённом флаге, guest — если фича не в
`deniedFeatures` и не отозвана токеном/кастомной ролью. Токен с pin-списком
прав без `whiteboard`/`annotations` не сможет пользоваться фичей даже при
включённом флаге.

При выключенном флаге:

- `welcome` не содержит `whiteboard`/`annotations`;
- любые `whiteboard.*` / `annotation.*` фреймы отклоняются
  `error{code:"unauthorized"}`;
- кнопки в виджете не рендерятся.

## 2. Модель штриха

Обе поверхности используют один формат штриха:

```json
{
  "id": "wb-m2x9-1-ab12cd34",
  "seq": 7,
  "tool": "pen",
  "color": "#3b82f6",
  "width": 0.012,
  "points": [{"x":0.12,"y":0.3},{"x":0.28,"y":0.22}],
  "authorId": "1650…",
  "authorName": "Анна",
  "ts": 1794769961801
}
```

- **Координаты нормализованы** `0..1` по обеим осям, поэтому рисунок одинаково
  ложится на 1440px-десктоп и 390px-телефон.
- **`width` нормализован к высоте поверхности** (доля высоты): `0.006` /
  `0.012` / `0.02` — тонкая/средняя/толстая кисть. На рендере ширина
  ограничивается снизу 1 CSS px, сверху — 28% высоты поверхности.
- `tool` в **клиентском** фрейме: `pen`, `eraser`, `undo`, `clear`.
  В хранимом штрихе только `pen`/`eraser`; `undo` и `clear` — команды.
- `color` — только `#rrggbb` (никакого CSS из клиента).
- `eraser` — обычный штрих, который рисуется в режиме `destination-out`:
  он стирает пиксели под собой и одинаково воспроизводится при replay.

## 3. Протокол (WebSocket `/ws`)

См. также таблицы сообщений в [api.md](api.md#10-websocket-сигналинг).

### Клиент → сервер

| type | Поля | Смысл |
|---|---|---|
| `whiteboard.open` | `{}` | открыть доску (идемпотентно); гость не может открыть закрытую host'ом |
| `whiteboard.close` | `{reason?}` | **host/moderator**: закрыть и заблокировать доску |
| `whiteboard.stroke` | `{id?, tool, color?, width?, points?}` | штрих (`pen`/`eraser`) или команда (`clear`/`undo`) |
| `whiteboard.sync` | `{}` | запросить актуальный снапшот (reconnect/повторное открытие) |
| `annotation.stroke` | `{id?, tool, color?, width?, points}` | штрих поверх текущей демонстрации экрана |
| `annotation.clear` | `{}` | ведущий показа или host/moderator: очистить пометки |

`points` для `pen`/`eraser` обязательны (1..1000 точек); для `clear`/`undo`
запрещены. `id` — клиентский UUID для дедупликации при ретраях.

### Сервер → клиент

| type | Поля |
|---|---|
| `whiteboard.open` | `{roomId, by:{id,name,role}, ts}` |
| `whiteboard.close` | `{roomId, by, reason, ts}` |
| `whiteboard.sync` | `{roomId, snapshot, reason:"join"\|"open"\|"close"\|"request"\|"clear"\|"undo"\|"trim", ts}` |
| `whiteboard.stroke` | `{roomId, stroke, revision, ts, trimmed?}` |
| `annotation.sync` | `{roomId, snapshot, ts}` |
| `annotation.stroke` | `{roomId, stroke, revision, ts, trimmed?}` |
| `annotation.clear` | `{roomId, by?, presenterId, reason:"moderator"\|"share_ended"\|"presenter_changed"\|"room_idle", ts}` |

`welcome` дополняется снапшотами при включённых флагах:

```json
{
  "type": "welcome",
  "...": "...",
  "whiteboard": {"roomId":"…","open":true,"locked":false,"strokes":[…],"revision":12,"updatedAt":…,"ts":…},
  "annotations": {"roomId":"…","presenterId":"…","strokes":[…],"revision":3,"updatedAt":…,"ts":…}
}
```

### Права

| Действие | guest | moderator | host |
|---|---|---|---|
| открыть доску (если не закрыта) | ✅ | ✅ | ✅ |
| рисовать / стирать | ✅ | ✅ | ✅ |
| `undo` | ✅ (только свой последний штрих) | ✅ | ✅ |
| `clear` | ❌ `unauthorized` | ✅ + аудит | ✅ + аудит |
| `whiteboard.close` (закрыть/заблокировать) | ❌ `unauthorized` | ✅ + аудит | ✅ + аудит |
| открыть **закрытую** доску | ❌ `unauthorized` | ✅ | ✅ |
| `annotation.stroke` (пока идёт показ) | ✅ | ✅ | ✅ |
| `annotation.clear` | ❌ | ✅ + аудит | ✅ + аудит (или ведущий показа) |

## 4. Состояние на сервере

`Room` владеет двумя in-memory слоями:

- `RoomWhiteboard` — `open`, `locked`, `strokes[]`, `revision`, `seq`;
- `RoomAnnotations` — `presenterId`, `strokes[]`, `revision`, `seq`.

Ничего не пишется на диск: доска живёт столько же, сколько комната (как чат,
опросы и breakout-планы). При переподключении клиент получает снапшот из
`welcome` (replay on join) и может попросить `whiteboard.sync`.

Лимиты памяти (жёсткие, применяются на сервере и зеркалятся виджетом):

| Лимит | Значение |
|---|---|
| Штрихов на доске | 200 (старые вытесняются) |
| Точек в одном штрихе | 1000 |
| Суммарно точек на доске | 20 000 |
| Байт в точках одного штриха (JSON) | 32 КБ |
| Штрихов аннотаций | 100 |
| Точек в одном штрихе аннотации | 1000 |
| Суммарно точек аннотаций | 8 000 |
| Байт в точках одного штриха аннотации | 24 КБ |
| Размер `reason` у `whiteboard.close` | 120 символов |

При вытеснении старых штрихов сервер рассылает `whiteboard.sync` с
`reason:"trim"`, чтобы у всех клиентов совпадала картина.

### Аудит

| Событие | Severity | Когда |
|---|---|---|
| `whiteboard.opened` | info | доска открыта (переход из закрытого состояния) |
| `whiteboard.cleared` | warn | host/moderator очистил доску (с `removed`) |
| `whiteboard.closed` | warn | host/moderator закрыл доску (с `reason`, `strokes`) |
| `annotation.cleared` | info | ведущий/модератор очистил пометки |

Штрихи **не** аудируются: это высокочастотное содержимое, в аудит попадают
только управляющие действия. В записях нет координат и текста.

## 5. Аннотации на демонстрации экрана

- Пометки привязаны к текущему показу: сервер вычисляет ведущего по
  `ParticipantState.screen` и сбрасывает слой при смене ведущего или завершении
  показа (`annotation.clear` с `share_ended` / `presenter_changed`).
- Оверлей в виджете позиционируется **по границам плитки** показывающего
  участника (self-share — плитка `data-self="true"`, иначе — по
  `data-participant-id`). Если плитка не отрендерена (виртуализация > 50
  участников, панель/мини-режим), оверлей скрыт — это осознанное ограничение.
- Рисовать может любой участник с правом `annotations`; очищать — ведущий
  показа или host/moderator.
- Клик по оверлею не блокирует плитку, пока режим пометок выключен:
  `pointer-events` включается только при активном режиме.

## 6. Виджет

- Кнопка «Доска» в баре управления (в island-режиме — в «⋯»).
- Панель: заголовок, индикатор блокировки, тулбар (ручка/ластик, 6 цветов,
  3 толщины, undo, очистка), canvas с сеткой, «Завершить доску» для
  host/moderator, статус `aria-live`.
- Кнопка «Пометки» появляется, когда кто-то показывает экран; включает оверлей
  и компактный тулбар (цвета/толщины/очистка/выход).
- Pointer Events + `touch-action:none`: мышь, перо и палец; второй палец
  игнорируется, штрих завершается на `pointerup`/`pointercancel`.
- Локальный штрих рисуется сразу (optimistic), сервер подтверждает его эхо по
  `id`; повторный фрейм с тем же `id` не дублируется.
- Если сервер отклонил/вытеснил штрих и прислал снапшот, неподтверждённые
  локальные штрихи старше 15 секунд отбрасываются (без «призраков»).
- CSS: `style-whiteboard.css`; светлая «бумажная» доска в обеих темах, чтобы
  все шесть цветов (включая тёмный) были читаемы у всех участников.

## 7. Проверка

Создайте комнату с включённой доской и войдите двумя участниками. Нарисуйте штрих каждым участником и проверьте синхронизацию. Для пометок повторите проверку поверх демонстрации экрана.

## 8. Ограничения и осознанные решения

- **Нет персистентности**: перезапуск сервера/закрытие комнаты теряет доску.
  Экспорт в PNG/PDF и серверное хранение — вне P2.
- **Нет курсоров участников** (опциональный пункт задания): штрихи
  синхронизируются, но live-курсоры не транслируются — это добавило бы
  высокочастотный канал (десятки сообщений/с) и отдельный rate-limit.
- **Одна доска на комнату**, без приватных досок и breakout-досок.
- Только свободное рисование: нет фигур, текста, стикеров, картинок,
  лазерной указки и «следования за ведущим».
- Аннотации повторяют **границы плитки**, а не letterbox-контент видео
  (`object-fit`), поэтому на широких экранах возможно расхождение в несколько
  пикселей по краям.
- На телефоне тулбар пометок горизонтально прокручивается (44px touch-targets
  по требованиям доступности); кнопка выхода всегда видна.
- `annotation.clear` гостя отклоняется; при этом гость может рисовать поверх
  показа — как в большинстве ВКС.
- Лимиты (200/20 000/32 КБ) выбраны для памяти одного процесса; при
  необходимости их можно поднять в константах протокола осознанно.
